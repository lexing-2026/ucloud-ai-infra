问题不是“能不能跑”，而是“单卡 48GB 能跑多快”

模型与硬件都被赛题锁死：Qwen3.8-27B-FP8（29GB 权重），1 张 RTX 4090 48GB。可变的是引擎、显存布局和投机解码。

四个硬约束

  • 上下文必须大于 32768，否则官方 harness 判配置异常
  • 质量 ≥ 官方 95%，即 IFBench 严格分 ≥ 0.76

  • 结果必须能在同规格机器上一条命令复现

这条赛道的三个真瓶颈

1. 权重带宽。FP8 权重 29GB，1008GB/s 显存带宽给出约 29ms/步的下限，只能靠投机解码减少步数。

2. FP8 GEMM 没有 4090 配置。两个引擎都落到 Triton block GEMM 的默认 tile，8K prefill 里 FP8 GEMM 占 73.8%，且小 M 时按 64 行补满。

3. 并发被静默限流。SGLang 默认 Mamba 池 15 槽，每请求占 5 槽，日志一行 warning 就把并发压到 3。

成功标准

官方 AIPerf 四档全部 100 请求零错误；IFBench 严格分 ≥ 0.76；30–60 分钟 soak 不崩、显存不涨。

核心创新：把 ForgeKernel 的调优流程用在 sm89 的 FP8 GEMM 上

ForgeKernel 的 kernel 面向 sm90/sm100，不能直接用。可用的是它的方法：默认实现作 reference，候选先过正确性，再在同一进程里计时，赢了才晋升。

1. Reference引擎默认 tile，5 个真实 shape，M=5/10/20/40 与 prefill M=8192
2. 候选BLOCK_M/N/K、GROUP_M、warps、stages，加 SWAP_AB、SPLIT_K
3. 正确性与 reference 平均相对误差 ≤1e-3，算错的 BLOCK_K=256 被拦下
4. 同进程计时交替测量，超过噪声阈值才晋升；25 次随机重启
5. 服务级复测装进 SGLang，用官方 100 请求验证，而不是只看微基准
